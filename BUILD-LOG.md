# Build log

Three lines a day: what I did, what broke, what I learned. This becomes the Builder Center write-up.

## Day 1, Tuesday 27 October 2026

**Did:** Created a personal AWS account (separate from my business), set the default Region to London, enabled MFA on the root user, created an IAM user `gibson-admin` with AdministratorAccess and MFA so I never work as root again, and set up this repository. Chose the creative feature: a working mixing desk where every fader is a strand of my life and the Studio channel unlocks my music.

**Broke:** Nothing yet. The browser automation I use could not reach my Chrome extension, so some console steps were done by hand.

**Learned:** Root is for billing emergencies only. An IAM user with admin rights plus MFA is the everyday account. An AWS Budget is an alert, not a spending cap, so it tells you about overspend rather than stopping it.

**Setup note:** Cloned to the mini PC and verified push access, 27 Oct.

**Audio, 27 Oct (afternoon):** Researched ambient sounds on Freesound, Pixabay and BBC Sound Effects. Chose Freesound CC0 only, because the loops sit in a public repo and both Pixabay and the BBC forbid redistributing files. Downloaded six originals, built the loops with ffmpeg on the mini PC (20 s excerpts, mono, normalised to about -18 dB, 0.2 s fades, 128 kbps MP3, 2 MB total). Learned: "free to download" and "free to redistribute" are different questions, and a public GitHub repo is redistribution.

**Site build, 27 Oct (afternoon):** Built index.html, css/styles.css, css/desk.css and js/main.js with the three core sections, the sticky nav carrying the "Hear my story" hint, and a text fallback that renders all seven stories from channels.js. Checked at 1280px and 390px. The desk section is a shell until the weekend; desk.js is next.

**Deploy, 27 Oct (late afternoon):** Connected AWS Amplify Hosting (Europe, London) to the GitHub repo. The GitHub authorisation popup was blocked by Chrome at first; allowed popups for the console and narrowed the Amplify GitHub App to this one repository. First deployment succeeded with no build command and output directory `/`. Live at https://main.dbthjbi29n1oo.amplifyapp.com. Pushed a README change and watched Amplify redeploy on its own, which proves the pipeline. Set a $13 (about £10) monthly budget with email alerts at 80% actual and 100% forecast. Wrote SETUP-GUIDE.md so anyone can repeat the whole day by hand. Learned: Amplify's GitHub link is an app installation on the GitHub side; a static site needs no build step; a budget is an alert, not a cap.

**Theme refresh, 27 Oct (evening):** Re-themed the whole site to The Unsaid Sound palette: near-black purple base, plum sections, violet primary, magenta accent, white headings and lavender body. Body text up to 18px (17px on phones), nav 17px. Cards and buttons given layered shadows, a top-edge highlight, hover lift and press response. Added a proper mobile menu (button with aria-expanded, closes on link, Escape and outside click), kept the "Hear my story" hint outside the menu so it is visible at every width, added waveform and equaliser motifs in SVG. Checked contrast on every text/background pair (lowest 5.08:1), twelve viewport widths for overflow, 200% zoom and reduced motion. Broke: the hero glow caused horizontal scroll on phones until clipped; the hint fell inside the collapsed menu until moved out. Learned: absolutely positioned decoration needs overflow clipping, and "visible hint" has to be checked at phone width, not assumed.

**Contact and booking, 27 Oct (evening):** Added a Contact section (heading "Let's talk about your next project"), a Contact nav link, a compact call-to-action band after Projects, and contact links in the footer. The form (name, email, optional phone and enquiry type, message) has visible labels, autocomplete, inline errors, loading, success and failure states, duplicate-submit protection, a honeypot and a minimum fill time. It posts to an API Gateway endpoint backed by a Lambda that sends through SES with Reply-To set to the visitor; code and console steps are in backend/. Until the endpoint is configured the form stays hidden and an email button shows instead, so nobody meets a form that cannot deliver. Booking is iMeetify (30-minute online call): a direct link plus a click-to-load embed with a fallback link. Wrote privacy.html. Verified links: LinkedIn and the booking page opened and checked; Facebook and Instagram supplied by me and not yet opened by the assistant. Tested with a mocked backend: validation, focus to first error, sending state, success, 502 and network failure all behave. Learned: a contact form on a static site is really three AWS services, and the sender address has to be verified in SES before anything can send.

**Welcome video card, 27 Oct (evening):** Added "A personal welcome from Gibson" beneath the contact form in the left column, with a reserved 16:9 frame so nothing shifts when the video arrives. No video has been recorded yet, so it shows "Welcome video coming soon" over a static purple waveform rather than a play button that does nothing. The source is one object at the top of js/welcome-video.js (YouTube, Vimeo or a self-hosted mp4); external players load only after the visitor presses play, through the no-cookie YouTube domain or Vimeo with do-not-track. Verified at 1366, 820 and 390px: aligned with the form, booking stays right on desktop, stacks form, video, booking, social on smaller screens, no overflow, no console errors; the configured-video path tested with a stand-in URL (play button labelled, keyboard operable, iframe titled, fullscreen allowed, invalid URLs keep the placeholder).

**Podcast section, 27 Oct (evening):** Added "The podcast" on the home page between Projects and the contact call-to-action: a Latest episode card with a "Podcast player coming soon" placeholder and a Listen and watch card linking the SEND Life Transition YouTube channel. The real player is one object at the top of js/podcast.js (Spotify, Apple Podcasts or YouTube) and loads only when a visitor presses Load player. Verified at seven widths with no overflow and no console errors; the Spotify path tested with a stand-in URL.

**Gallery, case studies and SEO, 27 Oct (night):** Audit first: the site is static HTML on Amplify, so Framer marketplace plugins (including React Export) do not apply and nothing was installed. Built a project gallery from one data model (js/projects.js): seven projects, four real categories, keyboard-operable filters with a pressed state, a live status line, an empty state, and the filter kept in the URL hash so a view can be shared. Each card shows a colour-keyed tile, category, summary, my role, and visible Case study and Visit links. Added project.html, a case-study template that reads the same data: overview, problem, role, approach, tools, outcomes, lessons and related projects, with outcomes left empty where nothing is verified rather than invented. Hero actions made consistent (View projects, Book a call). Sections now stop beneath the sticky header. Added canonical, og:url, Person structured data from verified profile facts, robots.txt and a sitemap. Tested: all seven case-study URLs and the not-found state, filters by click, arrow keys and deep link, seven widths without overflow, case page at 200% zoom, no console errors. Home page local payload is 14 KB over 11 requests before fonts. Editorial tasks recorded in the data file: real screenshots for Gibcom, AIBOS and the desk; figures for Clara once measured.
